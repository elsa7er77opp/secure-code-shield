# Secure Code Shield Reference Observations

The owner’s supplied reference is the visual source for the application identity. Its upper-right launch globe is the cleanest instance of the fractured green sphere because it does not contain the shield overlay used on the left launch panel.

The extracted application mark must crop only the globe itself. The `Starting Secure Code Shield` label and lime progress bar beneath it are launch-screen content, not part of the desktop icon or persistent product mark. The current crop boundary is therefore limited to the upper globe region of the reference image.

Visual check: a square source crop extending to the reference’s lower edge retained part of the launch label inside the circular icon. The production extraction must stop above that label and use a transparent 512px canvas to center the globe independently.

Generated-icon review: the first two original globe candidates established the desired dark segmented geometry and lime fracture direction, but both retained visible magenta generation-background artefacts and carried too much surface detail for a small icon. They are rejected as production assets. The final asset must preserve the clean black/graphite/lime sphere while removing every non-lime background artefact and simplifying the silhouette for 32px readability.

Logo decision update: no globe is approved. Every screenshot crop and every generated candidate is rejected and must remain outside the product. The desktop shell uses only a neutral temporary code mark until the owner explicitly selects a new logo direction.

Trademark selection criteria: select one original mark only after it remains legible as a 32px icon, has a single clear silhouette, contains no wordmark/card/checkerboard matte, uses true alpha outside the mark, and keeps the lime signal limited to the defensive-code cue. The owner reference defines the security mood, not an asset to crop or copy.

Trademark candidate review: candidates A and B have usable dark globe-and-shield hierarchy, but both carry fuchsia edge and horizontal-line artefacts that violate the clean-alpha requirement. Neither is approved. Any final selection must eliminate these artefacts and reduce surface complexity before use at Windows icon sizes.

Trademark selection: the refined direction uses a deliberately simplified dark globe with a central lime shield and code cue. It retains the owner reference's enterprise defense mood without reusing the source image. Its checkerboard preview matte is replaced by a true-alpha circular silhouette during asset packaging; only that clean-alpha packaged asset may enter the desktop application.

Packaging review: the first circular alpha mask still exposed checkerboard pixels inside empty parts of the crop. It is rejected. The final packaging pass removes the high-value preview-matte pixels by color while retaining the dark graphite and lime trademark geometry; the asset is not adopted until the post-package alpha check confirms the matte is absent.

Trademark final review: the accepted mark is a purpose-drawn near-circular graphite grid globe with a centered lime shield and geometric code cue. It has no card, wordmark, screenshot crop, orbit ring, checkerboard matte, or background. Its reduced visual vocabulary is intentional so it remains legible at desktop-icon sizes and stable across the splash, login, and workbench.
